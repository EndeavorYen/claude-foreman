# 實例：go-mon 0.31（試玩後的四件事＋補流程測試）

第二次實跑，2026-11-19。主模型 Opus，雲端 session。探測：子代理照指定跑在 `claude-haiku-5-5`，什麼都不做的派遣 72k token。

## 任務

四個角色試玩後留下的事，加上前一版沒有流程測試的新功能。三個設計問題（成就、前幾站電腦強度、大人區）在第一批 worker 跑的時候問使用者，回答回來就變成第二批單元。

## 計畫與結果

| 單元 | 模型 | 驗證 | 工作目錄 | 結果 |
|---|---|---|---|---|
| U1 三個 0.30 功能的流程測試＋題目難度星星 | sonnet | 關卡 | 主線 | 一次通過 |
| U2 程式產生 16 題「連接」題＋答案線＋接進練習 | sonnet | 關卡＋驗證者（sonnet） | worktree | 驗證者判不通過 → 接續同一個 worker 重做 → 第二位驗證者通過 |
| U3 成就改成看「自己做到」＋大人區按住 2 秒 | sonnet | 關卡 | worktree | 一次通過 |
| U4 調前幾站電腦、用模擬小孩重新量 | sonnet | 關卡 | worktree | 一次通過（一個指標差 1%，寫進交付說明） |

成本行：

```
foreman：opus 規劃＋驗收｜claude-sonnet-5-5 ×7（681k tok, 74 分）｜子代理合計 681k tok（其中固定開銷約 505k＝72k×7 次）
｜重派 1｜關卡 1 擋下 0｜驗證者抓到 1｜交付 4、擱置 0
```

（不含探測那一次 72k。驗證者第一次的 FAIL 裡有 3 道題教錯。）

## 學到的事

- **驗證者又一次抓到工頭的規格漏洞。** U2 的交接說明只要求「白棋切斷就吃得到一塊」，沒寫「切斷的那顆白棋本身不能馬上被吃」和「每個正解都要真的連起來」。worker 照規格做、測試全過，驗證者用棋理一看：3 題切斷的白棋只有一口氣（黑棋直接吃掉，題目不成立），2 題把不是連接的下法存成正解。分類是**規格**錯，同一層重做；用 SendMessage 接續同一個 worker（它的 context 還在），補兩條條件，第二次通過。
- **攤平材料、直接貼進 prompt。** 兩次驗證都是先用一支小腳本把 16 題的盤面、答案、讀棋結果印成 240 行，貼進 prompt、要它不用工具。一次 86k、一次 89k，只比固定開銷多 1.4～1.7 萬。
- **worker 的擔心也要自己驗。** U2 回報「初學者強度 0 還是拿不到今天的練習」，工頭跑一行就發現其實拿得到 3 題。`unsure` 要讀，但它說的不一定對。
- **行為牽連要寫進範圍。** U2 會讓「連起來」第一次有題目，U1 檔案裡有一條測試正好在測「連起來沒有題目時改成陪練一盤」。兩個單元不搶檔案，但合起來會壞；把「那條測試改用雙叫吃」寫進 U1 的範圍，合併後一次通過。
- **worktree 讓建置不互相踩。** U1 要 build 遊戲跑流程測試，U2 同時在重寫題庫資料檔。U2、U3、U4 各開一個 worktree，`node_modules` 用連結的。整合：在 worktree 開分支 commit，回主線 merge；三個單元改同一個測試檔的不同位置，git 自己合好了。（這次手動做；之後用 `foreman worktree`。）
- **不要改寫歷史。** 推之前想照舊版 skill 寫的「`reset --soft` 再 commit、強制推送工作分支」把四個 WIP commit 合成一個，被環境的安全檢查擋下。改成從 main 開新分支 `merge --squash`、確認和測過的完全一樣再推，什麼都不用改寫。
- **固定開銷仍是成本主體。** 7 次派遣 681k，其中 505k 是起跳價。這次換來的：主線沒有被 16 題的讀棋輸出和模擬數字塞滿、四個單元平行跑，以及驗證者抓到的 3 道教錯的題。
