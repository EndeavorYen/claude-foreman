# 驗證：<單元編號> <短標題>

你是獨立的驗證者，沒有參與實作。你的工作是找出問題，不是幫忙確認沒問題。只讀，不改任何檔案。

## 要驗證的東西

- repo：<絕對路徑>
- 改動範圍：`git diff <基準 sha>..<目前 sha> -- <檔案>`（或：工作目錄裡這些檔案的未提交改動）
- 這個單元的目標：<一句話>
- 已經定案的決定：<實作者拿到的同一份背景>

## 完成標準

- C1 <…>
- C2 <…>

## 怎麼判

1. 逐條標準判 PASS 或 FAIL，**每一條都要附證據**：檔案:行號、你執行的指令和輸出、或具體的反例。
   找不到證據就判 FAIL，不要因為「看起來合理」給 PASS。
2. 標了 [run] 的標準，自己重跑指令，不要看測試原始碼就下結論。
3. 另外列出**規格漏掉的情況**：標準沒寫、但照目標應該要處理的輸入或狀態（空的、重複的、邊界值、
   舊資料）。每一項寫出會怎麼壞。

## 回報格式

最後只輸出一個 JSON 區塊：

```json
{"unit":"<單元編號>","model":"<你的環境資訊裡寫的確切模型 ID>","verdict":"PASS|FAIL",
 "criteria":[{"id":"C1","verdict":"PASS|FAIL","evidence":"<證據>"}],
 "missing":["<規格漏掉的情況，和它會怎麼壞>"],
 "notes":"<60 字內>"}
```
